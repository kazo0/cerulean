# Installing curmudgeon on other agents

`skills/curmudgeon/SKILL.md` is the whole persona. Everything else in this repo is that file wrapped in some agent's native format, generated by `scripts/build.mjs`.

## Quickest route per agent

| If you use | Do this |
|---|---|
| Claude Code | `/plugin marketplace add kazo0/curmudgeon` then `/plugin install curmudgeon@curmudgeon` |
| Gemini CLI | `gemini extensions install https://github.com/kazo0/curmudgeon` |
| Anything that reads Agent Skills | `npx skills add kazo0/curmudgeon -g` (add `-a codex -a cursor` to pick agents) |
| Anything else, or you want `/curmudgeon` and always-on | `git clone https://github.com/kazo0/curmudgeon && cd curmudgeon && ./install.sh --agent <id>` |

## What each route gives you

An agent can have up to three things:

1. **The skill.** The agent loads `SKILL.md` on demand when you ask for "curmudgeon mode" or invoke the skill the way that agent does it. On Claude Code the skill is also the `/curmudgeon` command.
2. **A command.** `/curmudgeon <level>` in the agent's own command, workflow, or prompt-file format, so you can switch levels without typing a paragraph.
3. **An always-on rule.** The persona applies to every response in the workspace without being asked.

`npx skills add` gives you the skill only. `install.sh` gives you the skill plus the command, and `--always-on` adds the rule. The Gemini extension gives you the command plus a context file that holds the rules dormant until you ask.

## install.sh

Run it from a clone. It needs bash 3.2 or newer, which is what macOS ships.

```
./install.sh --list                        agents, what each gets, which are detected on this machine
./install.sh --agent cursor --agent cline  install for specific agents into the current project
./install.sh --all                         install for every detected agent
./install.sh --global ...                  user scope (home directory) instead of the current project
./install.sh --always-on ...               also install the always-on rule or AGENTS.md block
./install.sh --dry-run ...                 print what would change, write nothing
./install.sh --force ...                   overwrite existing files, refresh existing blocks
./install.sh --uninstall ...               remove exactly what the same flags would have installed
```

It never overwrites a file without `--force`. Files it shares with you (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.rules`, and friends) get a block between `<!-- curmudgeon:start -->` and `<!-- curmudgeon:end -->` markers; the rest of the file is untouched, and `--uninstall` removes only the block.

## Uninstall

- `install.sh`: rerun the same flags with `--uninstall`.
- `npx skills add`: `npx skills remove curmudgeon`.
- Claude Code plugin: `/plugin uninstall curmudgeon@curmudgeon`.
- Gemini extension: `gemini extensions uninstall curmudgeon`.

## Regenerating

Edit `skills/curmudgeon/SKILL.md`, then:

```bash
node scripts/build.mjs          # rewrite every agent file
node scripts/build.mjs --check  # CI: fail if anything is stale
```

Never edit a generated file by hand. It will be overwritten, and the CI check will fail until it is.

## Caveats

- Agent config formats change often. The paths and frontmatter here were correct as of September 2026. If your agent moved something, open an issue or a PR against `scripts/build.mjs` and `install.sh`.
- Windows: the installer is bash. Use Git Bash or WSL, or copy files by hand from the table above.
- The always-on block is about 9,000 characters. Agents with small rule budgets (Windsurf global rules, some IDE assistants) will refuse it; use the on-demand rule or the skill instead.
